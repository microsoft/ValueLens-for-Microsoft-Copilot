# Sample data — try ValueLens with no tenant setup

Four CSVs that populate the dashboard end to end, so you can see how the numbers
land before wiring anything up to your own tenant.

| File | Feeds the template parameter | Rows |
|---|---|---|
| `copilot_interactions_sample.csv` | **Copilot Interactions File** | 13,337 |
| `copilot_users_sample.csv` | **Org Data File** | 170 |
| `agents_365_sample.csv` | **Agent 365** *(optional)* | 104 |
| `product_feedback_sample.csv` | **Feedback File** *(optional)* | 1,215 |

## Quick start

1. Open **[`../ValueLens - Local CSV.pbit`](../)** in Power BI Desktop.
2. When prompted for parameters, point each at the matching file above (full local paths).
3. **Load**.

That's it — no export, no app registration, no Fabric capacity, no Purview access.

> Use the template in **[`4. Local CSV/`](../)** — not `3. SharePoint/ValueLens - SharePoint.pbit`,
> which deliberately accepts SharePoint URLs only.

## This data is fabricated

Every value is generated by [`Build-SampleData.py`](Build-SampleData.py) from a fixed
seed. No row is copied, sampled or derived from any tenant, audit log or customer
export — the data is synthetic **by construction rather than by redaction**, which you
can confirm by reading the generator rather than by trusting a scrub.

Its *proportions* were tuned against aggregate counts from real deployments: how many
sessions are a single prompt, how Cowork work splits across shapes, which models are in
use, how feedback splits by type. That keeps each page looking the way it does on a
real estate. Only those shares informed the generator; no values were carried over.

- People have invented `first.last@contoso-demo.com` names and placeholder IDs (`00000000-…`)
- Organisations, job titles, agent names, offices, prompts and feedback comments are invented
- No real UPNs, tenant IDs, workspace endpoints or prompt text; SharePoint links use
  `contoso-demo.sharepoint.com`, and web citations point at public sites such as Microsoft Learn

It models a 170-person company in 14 organisations over three full months (June to
August 2026). About two thirds are licensed. There is a management hierarchy (CEO, org
heads, team leads, staff), adoption from power users down to lapsed and never-used
licences, and weekday-heavy usage.

## Coverage — every page has something to show

| Page | What the sample gives it |
|---|---|
| Adoption, Trend Heatmap, Leaderboard | 3,716 sessions across three months, weekday-heavy, on a working-hours curve; sessions from one turn to more than seven |
| Habit Formation | all four habit bands in the latest month (Beginner, Developing, Habitual, Power) |
| Activation, License Readiness, License Allocation | licensed seats that are active, inactive for 30–90 days and never used; unlicensed people with workarounds as licence candidates |
| Organisation slicers and tables | 14 organisations of different sizes, licence coverage and engagement |
| Task Breakdown, Estimated Value | Copilot, agents and Cowork across Word, Excel, PowerPoint, Outlook, Teams, Loop, OneNote, SharePoint and Edge |
| Cowork Readiness, Cowork Fit | all eight Cowork work shapes, plus some people who mostly chat with Cowork, so the WHO table has people to flag |
| Model Fit | GPT-5, GPT-4.1, Claude, Sonnet, Opus and GPT-6, so Well-matched, Over-specified and Under-specified all appear |
| Agent Registry | 104 registry entries in every lifecycle state: in use, deployed but not yet used, built in the tenant (owned and ownerless), catalogue and blocked. Three agents go quiet part-way through |
| User Feedback | 15 months of feedback across 11 types: thumbs, NPS, PSAT, feature surveys, ideas, bugs, smiles, frowns and more |

Share of interaction rows by slice:

| Slice | Share | What it is |
|---|---|---|
| Licensed Copilot | ~65% | Copilot Chat and Copilot in Word, Excel, PowerPoint, Outlook, Teams, Loop and OneNote |
| Unlicensed Copilot Chat | ~11% | free Copilot Chat, the licence-upgrade cohort, including agent use and file workarounds |
| Declarative agents | ~9% | Agent Builder agents, plus SharePoint agents |
| Copilot Cowork | ~8% | multi-step, multi-app work with human approval |
| Copilot Studio and Azure AI Foundry | ~4% | custom agents over line-of-business systems, including autonomous agents |
| Microsoft and partner agents | ~3% | Microsoft Scout, Researcher, Analyst, marketplace and line-of-business agents |

Resulting `Environment` mix: **Licensed ~88% / Unlicensed ~12%**. `Environment` is
licensing only; Cowork is flagged in `Agent Filter` (**Cowork ~8%**, beside **Agents ~16%**),
which is what the template's Tool pills and Cowork pages filter on. Cowork rows are
derived the way the processor derives them, from `cowork` appearing in the app host or
agent name, and link to the registry by the agent name `Copilot Cowork`. Each Cowork
session is planned as one work shape, with the MIME types and message reads that shape
logs. Scout appears as agent activity under the `Microsoft Scout` app host, including
outside office hours. Cowork and Scout adoption ramps up across the window and is gated
per person, rather than appearing fully formed on day one.

`agents_365_sample.csv` carries 41 registry columns, including `Entra Agent ID`,
`Is Blocked`, `Agent creator UPN` and `Agent creator source`, so the Agent Registry page
populates the same way it does from `Get-Agents365Registry.ps1`. 44 of
the 104 agents are used in the window; the rest are there to fill the other lifecycle
states.

`product_feedback_sample.csv` has the shape of the Microsoft 365 admin centre **Product
feedback** export (21 columns, verbatim headers). Thumbs up and down in the window are
tied to real sample sessions (same person, same app or agent, submitted minutes later).
The twelve months before the window add history and the survey types, so the monthly
trend has a year to show. Satisfaction is about 64% overall and varies by app and agent.
The same file also works on the Fabric path: drop it in `Files/product_feedback/` and run
`Copilot_ProductFeedback_Ingester`.

## Regenerating

```bash
python Build-SampleData.py --end 2026-08-31              # rewrites the CSVs in this folder
python Build-SampleData.py --users 400 --months 6        # bigger tenant, longer window
```

Run it from inside the repo — it imports the production classifier by relative path.
It prints a coverage report afterwards (sessions by tool, fit grades, Cowork shapes,
model fit, turn bands, habit bands, dormancy, organisations, feedback types), so you can
check a change still fills every page.

| Flag | Default | Effect |
|---|---|---|
| `--end` | last day of last month | last day of the window |
| `--months` | `3` | full months in the window |
| `--users` | `170` | people in the company |
| `--agent-share` | `0.20` | share of licensed sessions handled by agents |
| `--cowork-share` | `0.20` | share of sessions handled by Copilot Cowork, for people who have it |
| `--scout-share` | `0.08` | share of sessions handled by Microsoft Scout, for people who have it |
| `--unlicensed-agent-share` | `0.18` | share of unlicensed sessions that use an agent |

Cowork and Scout shares are also scaled by the adoption ramp and by whether each person
has that surface switched on, so the realised shares are lower than the flags.

Deterministic — the same seed and `--end` give byte-identical output, so a regenerated
file produces an empty diff unless you actually changed something.

## Why CSVs and not a demo `.pbix`

A `.pbix` would be one click instead of two, but it embeds its data in a compressed
model where **you cannot review it**. A byte-scan of a `.pbix` reports "no emails, no
domains" whether the data is synthetic or a live tenant export, because the payload is
compressed — so the check that feels reassuring is the one that proves nothing. A
`.pbix` also carries file-level metadata that survives anonymising the data itself:
sensitivity labels, the source SQL endpoint in a parameter default, and the workspace
`DatasetId` it was published from.

CSVs are plain text. They diff in a pull request, and anything wrong with them is
visible to a reviewer. The generator being committed alongside means the provenance is
auditable rather than asserted.

## Also useful as a test fixture

Because the files satisfy the template's full column contract — 61 interaction columns,
84 org columns, 41 agent columns, 21 feedback columns — they double as a regression fixture for template
changes. If a model edit breaks the load path, loading this dataset surfaces it without
needing tenant access.

## Value model note

The generator **does not re-implement the classification maps**. It imports the
production classifier —
[`../scripts/Purview_CopilotInteraction_Processor_v4.0.0.py`](../scripts/) — and calls
its `compute_*` functions under the `aibv` profile for every derived column:
`Environment`, `Behavior_Enriched`, `Value_Outcome`, `Usage_Mode`, `Expertise_Role`,
`Efficiency_Breakdown`, `Autonomy_Pattern`, `Behavior_Source`, `Human_Baseline_Min`,
`Workflow_Action`, `Web_Grounded_Signal`, `Behavior_Plausible`, `Delegation_Event_Key`,
`Agent Publish Status` and the rest. The six agent-type columns (`Agent_Type` and its
companions) come from the processor's `make_agent_type_describer`, so every Researcher and
Analyst row lands in a Microsoft first-party category and the Agent Registry page's agent-type
slicer and chart populate. Copilot Cowork rows carry no agent ID, so they show as
**Unclassified agents**, as they would from a real export.

So the sample data **cannot drift from the shipping pipeline**: change the taxonomy or
the baselines in the processor, re-run the generator, and the CSVs follow. There is no
duplicated map to keep in step.

Every behaviour the generator emits is a member of the processor's Behavior Value Map,
so agent rows contribute real modelled hours instead of silently scoring zero. A small
number of rows carry a blank `Human_Baseline_Min` — those are behaviours the processor
itself holds outside the BVM bridge (`Email Triage`, `Email Thread Summary`,
`Spreadsheet Analysis`, `Cross-Org Agent`), and the blank is the correct classifier
output, not a gap in the fixture.

Hours saved and assisted value therefore compute exactly as they would on real data —
the totals are fictional, but the arithmetic behind them is the shipping model, not a
placeholder.

`Agent_LinkID` is deliberately not emitted: the template derives it by joining these
rows to the Agents 365 registry, so shipping it in the CSV breaks the load.
